# Loki — домофон в Home Assistant

Интеграция Home Assistant для облачного домофона: камеры и двери с кнопками открытия,
события входящего звонка для автоматизаций и связка с [Frigate](https://frigate.video/)
для распознавания лиц.

Название — игра слов: **lock** (замок) → **Loki**.

> ⚠️ **Для Home Assistant нужен отдельный номер телефона.** Подробнее — в разделе
> [«Авторизация»](#авторизация).

## Возможности

| Что | Статус |
|---|---|
| Авторизация по номеру телефона + SMS прямо в UI | ✅ |
| Камеры дверей и обычные камеры (RTSP, снимки) | ✅ |
| Кнопки открытия дверей | ✅ |
| События звонка, сущности звонка, blueprint с уведомлением | ✅ |
| Приём входящих звонков по SIP (источник события) | ✅ |
| Распознавание лиц через Frigate → событие | 🚧 |

## Установка

### Через HACS (как пользовательский репозиторий)

1. HACS → три точки → **Пользовательские репозитории**.
2. URL: `https://github.com/william-aqn/home-assistant-domofon-hacs`, категория **Integration**.
3. Установить **Loki**, перезапустить Home Assistant.
4. **Настройки → Устройства и службы → Добавить интеграцию → Loki**.

## Авторизация

При настройке сначала показываются условия использования — их нужно принять, затем
ввести номер телефона и код из SMS.

> ⚠️ **Сервис допускает только один активный сеанс на один номер телефона.**
> Если ввести здесь номер, который используется в мобильном приложении оператора,
> **это приложение будет разлогинено**.
>
> **Заведите для Home Assistant отдельный номер** и добавьте его в список разрешённых
> номеров через официальное приложение (обычно допускается до двух номеров на квартиру).

Токен доступа обновляется автоматически. Токен обновления живёт около 90 дней
и сервером не продлевается, поэтому примерно раз в квартал интеграция попросит
войти заново по SMS — это штатное поведение.

## Сущности

- `camera.*` — по одной на каждое устройство с камерой. Двери включены по умолчанию,
  обычные камеры создаются выключенными (включаются одним кликом).
- `button.*_open` — кнопка открытия для каждой двери.
- `event.*_doorbell` — звонок в дверь (тип события `ring`).
- `binary_sensor.*_call_active` — идущий вызов. Снимается автоматически через 120 с,
  если звонок не завершился явно.
- `switch.*_sip` — приём звонков по SIP (по умолчанию **выключен**, см. ниже).
- `sensor.*_sip_status` — что делает SIP-клиент прямо сейчас.

Двери без камеры получают только кнопку открытия и сущности звонка.

Новые двери и камеры появляются сами при очередном опросе. А вот **переименование**
устройства попадёт в Home Assistant только после перезагрузки интеграции.

## Действия

| Действие | Что делает |
|---|---|
| `loki.open_door` | Открывает дверь по её идентификатору |
| `loki.simulate_ring` | Порождает событие звонка — для проверки уведомлений без реального звонка |
| `loki.hangup` | Завершает активный вызов |

## Приём звонков по SIP

Домофон звонит на SIP-аккаунт квартиры. Loki может слушать этот аккаунт и превращать
звонок в событие Home Assistant — тогда уведомление с видео и кнопкой «Открыть»
приходит от настоящего звонка, а не от `simulate_ring`.

**Переключатель `switch.*_sip` выключен по умолчанию, и это не осторожность ради
осторожности.** У аккаунта один адрес (AOR), и на нём уже может быть зарегистрирован
телефон жильца. Вытеснение его привязки со стороны телефона выглядит никак: он просто
перестаёт звонить, без ошибок и уведомлений. Поэтому:

- Прежде чем регистрироваться, Loki **смотрит**, кто на аккаунте уже есть, и при чужой
  привязке **не регистрируется вовсе** (`sensor.*_sip_status` = `blocked`).
- Перед самой первой регистрацией он около десяти минут наблюдает за аккаунтом:
  одна пустая выборка ничего не доказывает — спящий телефон выглядит так же
  (`sensor.*_sip_status` = `baseline`).
- Первая регистрация берётся на минуту, чтобы ошибка вылечилась сама.
- После регистрации Loki перепроверяет, что ничего чужого не исчезло. Если исчезло —
  снимает свою привязку и останавливается (`evicted`), а в «Настройки → Система →
  Ремонт» появляется карточка с объяснением.
- Loki **никогда не отвечает на звонок** (`200 OK`) и никогда не шлёт `6xx`: и то и
  другое отняло бы звонок у телефона жильца. Максимум — `180 Ringing`, а отказ идёт
  как `486 Busy Here`, то есть только по своей ветке.

Выключение переключателя действует немедленно и не требует перезагрузки интеграции —
это кнопка отката в один тап. Повторное включение снимает защёлку, если клиент
остановился окончательно.

**Заведите для Home Assistant отдельный номер** — тогда SIP-аккаунт будет свой,
и весь этот риск исчезает.

Дверь, с которой идёт звонок, определяет сервер по SIP-адресу звонящего. Loki не
угадывает её по названию: результат решает, какую дверь откроет кнопка в уведомлении.

## Уведомление с видео и кнопкой «Открыть»

При звонке интеграция публикует событие `loki_event` с `type: call_incoming`.
Готовый blueprint отправляет на телефон actionable-уведомление со снимком с камеры
двери и кнопкой «Открыть»:

[![Импортировать blueprint в Home Assistant](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fgithub.com%2Fwilliam-aqn%2Fhome-assistant-domofon-hacs%2Fblob%2Fmain%2Fblueprints%2Fautomation%2Floki%2Fring_notify_open.yaml)

HACS не скачивает blueprint'ы (такой категории у него нет) — импортируйте по ссылке выше.

Проверить всю цепочку без реального звонка: **Инструменты разработчика → Действия →
`loki.simulate_ring`**, указать id двери.

Для автоматизаций надёжнее триггер по шине `loki_event`, а не по состоянию
`event.*_doorbell`: event-сущность восстанавливает состояние после перезапуска
Home Assistant и на старте покажет данные прошлого звонка.

Полезная нагрузка события:

```yaml
event_type: loki_event
data:
  type: call_incoming        # call_incoming | call_ended
  device_id: 695
  device_name: Центральный вход
  entity_id: camera.loki_tsentralnyy_vkhod   # null, если камеры нет
  sip_uri: null              # заполняется, когда появится SIP
  call_id: sim-…
```

## Карточка двери: видео, кнопка открытия и состояние потока

Встроенный диалог камеры Home Assistant настроить нельзя — его вёрстка и кнопка
«Сделать снимок» принадлежат Home Assistant. Зато карточка на дашборде делает всё,
что нужно, средствами ядра: показывает картинку, кладёт поверх неё кнопку открытия
и предупреждение, когда живое видео недоступно.

Подставьте свои `entity_id` вместо `<дверь>` и `<аккаунт>`:

```yaml
type: picture-elements
camera_image: camera.<дверь>
# auto: снимок в обычном состоянии, живое видео при открытии карточки
camera_view: auto
elements:
  - type: service-button
    title: Открыть
    service: button.press
    service_data:
      entity_id: button.<дверь>_open
    style:
      right: 4%
      bottom: 4%
      background: rgba(0, 0, 0, 0.55)
      color: white
      border-radius: 8px
      padding: 6px 14px
      font-size: 15px

  # Появляется только когда медиа-хост недоступен.
  - type: conditional
    conditions:
      - condition: state
        entity: binary_sensor.loki_<аккаунт>_video_stream_reachable
        state: "off"
    elements:
      - type: state-label
        entity: binary_sensor.loki_<аккаунт>_video_stream_reachable
        prefix: "Живое видео недоступно — показан снимок "
        style:
          top: 6%
          left: 50%
          transform: translate(-50%, 0)
          background: rgba(180, 30, 30, 0.85)
          color: white
          border-radius: 6px
          padding: 4px 10px
          font-size: 13px
```

Если нужен просто список дверей с кнопками, без видео, подойдёт и штатная карточка
устройства: все сущности одной двери сгруппированы в одно устройство.

## Распознавание лиц (Frigate)

Интеграция сама лица не распознаёт — она использует Frigate и лишь связывает его
события с конкретной дверью домофона. Ключевое:

- **Не направляйте Frigate на все камеры.** Узкое место — декодирование, а не детекция,
  и `detect: fps` его не снижает. Хватит 1–2 главных дверей.
- **Только через go2rtc** (встроен в Frigate): одно исходящее соединение к облаку
  разделяется между детекцией, записью и просмотром.
- Распознавание лиц требует CPU с **AVX+AVX2** и не ускоряется Google Coral (Coral —
  только детекция объектов). Для точной модели нужен Intel iGPU (OpenVINO) или GPU.
- Требуется Frigate **0.17.2+**.

> Автоматическое открытие двери по распознанному лицу намеренно не поддерживается:
> ни один движок не выполняет проверку живости, а подъездная дверь — общее имущество.
> Blueprint по лицу уведомляет, но не открывает.

```bash
pip install ruff pytest pytest-homeassistant-custom-component pyyaml
```

Home Assistant — они проверяют разбор данных и правила протокола.
